Spec defects block correct implementation

The 2026-09-09 review found: §2.5 lists ShutdownerWithError as ShutdownWithError() error — actual source is Shutdown() error (di_lifecycle.go:82-83). §4 misses the six Override* functions and As/AsNamed. Implementing from the uncorrected table would silently miss every ShutdownerWithError implementer. Fix spec before code.

Frozen-fixture discipline

CV's working tree already contains an uncommitted Store.HealthCheck fix — the golden HW-1 fixture exists only at CV HEAD. All fixtures must be frozen snapshots under testdata/, never live references into CV.

06Risks & Guardrails

!
Spec defects corrupt downstream code A01–A08 execute before any analyzer code; the §2.5 signature error would silently miss every ShutdownerWithError implementer.
!
Fixture rot CV is being fixed in parallel (uncommitted Store.HealthCheck in worktree). Snapshots at HEAD, frozen under testdata/.
!
HW-4 noise CV has 53 lazy Provide sites; HW-4 fires on each implementer. Allowlist (M18) is load-bearing from Tier 2, not optional.
+
Stolen, proven patterns Compile-gated goldens, version-gating tests, fuzz-never-panics, --check/--strict contract, and ignore-directive semantics come from go-auto-upgrade's production-tested playbook.
!
Severity ≠ confidence Every finding carries both axes (go-finding model). HW-1/3/5 are type facts → confidence Full; HW-4 is a judgment call → Medium. Exit codes key on confidence, not severity.
+
One finding model family-wide go-finding gives JSON, SARIF, suppression-with-expiry, filters, and merge/dedup without a converter layer (measured 1,200–1,900 LOC glue cost avoided).
